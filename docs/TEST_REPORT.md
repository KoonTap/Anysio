# ผลตรวจระบบก่อน upload 4

วันที่ตรวจ: 26 ตุลาคม 2569

## ขอบเขตและวิธีตรวจ

เทียบข้อกำหนดในเอกสารโจทย์โครงงานเว็บและเกณฑ์คะแนน 9 หน้า กับโค้ดปัจจุบัน ทดสอบ HTTP ด้วย Supertest บน Node.js 24.21.0 และ **PostgreSQL 18.6 จริง** โดยสร้างฐานข้อมูลชั่วคราวจาก schema/seed และใช้ PostgreSQL Session Store เช่นเดียวกับระบบ

ผล: **ผ่าน 202 รายการตรวจ** ครอบคลุมทั้งกรณีสำเร็จและกรณีที่ต้องปฏิเสธ คำขอเพื่อรับ CSRF Token และ assertion ย่อยบางรายการไม่ได้รวมในจำนวนนี้

อ่านฐานข้อมูลใช้งานจริงเพื่อตรวจรายการสิทธิ์เท่านั้น: พบ 4 Role และ 26 Permission ครบ สิทธิ์เริ่มต้นของ Owner, Receptionist และ Vet ไม่ขาด การทดสอบที่สร้าง/แก้/ลบข้อมูลทำในฐานชั่วคราวทั้งหมด และล้างฐานนั้นเมื่อเสร็จ

## ปัญหาที่พบและแก้ก่อนส่ง

เมื่อ PostgreSQL ปฏิเสธการลบสัตว์ที่มีนัดอยู่ด้วย `ON DELETE RESTRICT` ส่งรหัส `23001` ซึ่งเดิม Error Middleware ไม่รองรับ ทำให้เว็บตอบ 500 แม้ฐานข้อมูลป้องกันการลบได้ถูกต้อง

แก้ `middleware/errors.js` ให้รองรับทั้ง `23503` และ `23001` แล้วตอบ 409 พร้อมข้อความ “รายการนี้มีข้อมูลใช้งานอยู่ จึงลบหรือเปลี่ยนแปลงไม่ได้” ทดสอบชุดเต็มหลังแก้ผ่านทั้งหมด รวมกรณีลบ Role ที่ยังมีผู้ใช้

## สิ่งที่ยังไม่ใช่การยืนยันว่าครบงานส่ง

- มี Source Code, วิธีติดตั้ง, schema, seed, บัญชีตัวอย่าง และคู่มือ MVC ใน repository
- **ยังไม่พบ ER Diagram, Access Matrix สำหรับส่งอาจารย์ และสไลด์ใน repository นี้** ต้องตรวจหรือเตรียมแยก; ตาราง ACL บนเว็บไม่แทนเอกสาร Access Matrix ที่ต้องส่ง
- ยังต้องสาธิตระบบจริงและตอบคำถามตามเวลาที่อาจารย์กำหนด ผลทดสอบนี้ไม่ใช่การรับรองคะแนน
- ไม่ได้ทำ load test, penetration test เต็มรูปแบบ หรือทดสอบทุกเบราว์เซอร์/ขนาดหน้าจอมือถือในรอบนี้
- การทดสอบความคงอยู่ใช้การเปิด Express instance ใหม่ ไม่ได้รีสตาร์ตบริการ PostgreSQL ของผู้ใช้
- การตรวจไฟล์ครอบคลุมชนิด/ขนาด/CSRF/สิทธิ์และการจัดเก็บที่ระบุข้างต้น ไม่ได้ทดสอบข้อมูลภาพเสียทุกรูปแบบที่เป็นไปได้

## ลำดับสาธิตที่แนะนำ

1. Owner เพิ่มสัตว์ ขอนัด และแนบภาพ
2. Receptionist ยืนยันนัด/เลือก Vet และเช็กอิน
3. Vet บันทึกผล แล้ว Owner เปิดดูผลตรวจ
4. ใช้ Owner พิมพ์ URL `/admin/users` และ `/api/admin/users` เพื่อแสดงการปฏิเสธ
5. Admin เพิ่ม Role ใหม่และย้ายบัญชีทดสอบไป Role นั้น
6. เพิ่ม Permission จากฟังก์ชันที่รองรับและให้สิทธิ์ผ่าน ACL; ทดลองด้วย Session เดิม แล้วถอนสิทธิ์และทดลองอีกครั้ง
7. แสดงการปฏิเสธภาพปลอมหรือเกิน 5 MB และการเปิดภาพของเจ้าของอื่น
8. เปิดหน้า Log กรองการเปลี่ยน Role/ACL อัปโหลด และการถูกปฏิเสธ

ควรสาธิตกับฐานข้อมูลสำเนา/ข้อมูลตัวอย่าง เพื่อไม่ต้องแก้สิทธิ์หรือรายการนัดที่ต้องการเก็บไว้
